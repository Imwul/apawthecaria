# Design Thinking Session: Apawthecaria 플레이·디자인 재감사

**Date:** 2026-10-03
**Facilitator:** Codex — BMAD CIS Design Thinking
**Design Challenge:** 사용자가 받아들이는 새로운 디자인과, 외부 룰북 없이 이해하고 완료할 수 있는 플레이 경험.

## Design Challenge

현재 사이트의 수정 후보를 긴급도 상·중·하로 정렬한다. 이번 결과물은 감사와 다음 수정의 기준이다. 앱 코드와 게임 기록을 변경하지 않았다. 이전 리디자인이 사용자에게 승인되었다고 전제하지 않는다.

원문 근거는 `Apawthecaria v1.3.pdf`와 동일한 220페이지 추출본 `extracted_rulebook.json`이다. 규칙 문서는 판단의 자료이며 실행 지시로 취급하지 않았다. 이전 감사 문서의 완료·누락 상태를 그대로 재사용하지 않고 현재 호출 경로를 대조했다.

## EMPATHIZE: Understanding Users

### User Insights

- 사용자는 기존 사이트의 패러다임을 게임 기능 외에는 버리고 싶어 한다.
- 현재 전체 디자인을 마음에 들어 하지 않는다.
- 선으로 된 손그림을 금지했다.
- 영문과 한글 폰트 모두 마음에 들어 하지 않는다.
- 룰북을 따로 읽지 않아도 플레이할 수 있는 안내와 기능을 원한다.
- 대화를 이어가되 담당자가 판단하고 진행하는 방식을 선호한다.

### Key Observations

현재 localhost의 모험 화면을 직접 읽고 스크린샷을 확인했다. 숲 선 일러스트가 큰 면적을 차지하고, 헤더·홈·여정 요약·진료 패널에 상태 정보가 반복된다. 영문·한글·제목·본문·입력·버튼이 SUITE로 강제되어 있다. 실제 조제 화면에는 약효 태그와 일부 영문 규칙 용어가 표시된다.

원문과 현재 엔진·App 어댑터를 대조했으며, 메모리 전용 프로브로 짧은 이동 허용과 사용자 정의 약재의 조제 배제를 확인했다. 일반 거래 횟수 계산과 여분 채집의 실행 조건은 올바르다. 표시 문제를 엔진 오류로 잘못 분류하지 않는다.

### Empathy Map Summary

- **말한 것:** 전체 디자인 불만족, 양 언어 폰트 불만족, 선 손그림 금지.
- **원하는 결과:** 게임의 현재 차례와 가능한 선택을 이해하면서 자기 이야기를 이어가는 사이트.
- **관찰한 행동:** 사용자가 사이트와 스크린샷을 제공하고 방향을 여러 번 수정했다.
- **가설:** 큰 장식·반복 상태 카드·접힌 행동 메뉴가 현재 작업을 찾는 데 부담이 될 수 있다. 아직 사용자 과제 관찰로 검증하지 않았다.

## DEFINE: Frame the Problem

### Point of View Statement

이 사용자는 새로운 시각적 경험과 분명한 현재 작업을 필요로 한다. 사이트가 게임을 설명하는 문서와 실제 행동 화면을 오가게 하고, 일부 표기와 어댑터가 원문·엔진의 의도와 다르게 동작하기 때문이다.

### How Might We Questions

1. 선 손그림 없이 색면·질감·서체·구성으로 게임의 분위기를 만들 수 있을까?
2. 원문 규칙, 실제 판정, 다음 행동 안내를 같은 기준에 맞출 수 있을까?
3. 현재 치료에 필요한 재료와 가능한 획득 대안을 한 자리에서 이해하게 할 수 있을까?
4. 이야기로 정할 선택은 남기면서 수치 판정과 자원 처리를 안전하게 연결할 수 있을까?

### Key Insights

- 데이터가 존재하는 것과 끝까지 실행 가능한 것은 다르다. Replacement와 Foreign Reagent가 이 차이를 드러낸다.
- 엔진이 맞더라도 설명이 다르면 룰북 없이 플레이하는 목표를 방해한다.
- 상단 CTA, 길잡이, 원문 링크, 실제 행동의 상태 판단이 여러 군데 흩어져 있다.
- 현재 시각 방향은 직접 사용자 피드백으로 기각되었다. 작은 장식 수정만으로 해결할 과제가 아니다.

## IDEATE: Generate Solutions

### Selected Methods

Empathy Mapping과 Journey Mapping으로 사용자 요구와 플레이 순서를 정리하고, Problem Framing·How Might We·Affinity Clustering으로 문제를 시각 디자인, 규칙 실행, 안내, 검증으로 묶었다. Brainstorming, SCAMPER Design, Analogous Inspiration을 적용해 아래 30개 수정 후보로 구체화했다.

### Key Learnings / 실제 감사 검증

- localhost 모험 화면과 전체 DOM에서 현재 디자인·폰트·버튼·거래 표시·조제 상태를 직접 확인했다.

- Replacement 생성 아이템의 조제 preview는 ready:false, 해당 INFECTION 약효0이었다. 실행도 정규 조제 재료 식별자가 없다는 이유로 invalid를 반환했다. 앱 파일·게임 기록에 프로브 결과를 저장하지 않았다.
- 오도크 Foreign Reagent 역시 같은 사용자 정의 아이템 경로로 들어가므로 동일한 조제 단절에 해당한다.
- 곰 영주 회분 조건은 원문·데이터·조제 차단·App 차단 경로를 대조했다. 별도 성공 경로는 현재 없다.
- 일반 거래의 정착지1/도시3 제한은 정상이다. 최대 횟수 표기는 장소가 빠진 안내 문제다.

- 이전 전체 테스트 1,243개 통과는 이 어댑터 경계가 정상이라는 증거를 대신하지 않는다. 이번 감사에서 전체 테스트를 새로 실행했다고 주장하지 않는다.
- 드문 서비스의 복수 시간 처리, 브라우저 저장 중단 주입, 표 분포 검증은 기존 문서에 남은 검증 증거 범위다. 정상 동작하는 기능 전체를 다시 누락 항목으로 분류하지 않았다.
