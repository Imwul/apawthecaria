# Design Thinking Session: Apawthecaria 시선의 강약과 장별 작업

**Date:** 2026-10-05
**Facilitator:** Codex — BMAD Design Thinking / Party Mode
**Design Challenge:** 3440×1440에서 큰 글씨를 유지하면서, 실제 작업이 중심이고 설명과 장식은 조용하게 받쳐주는 수첩을 만든다.
**Baseline:** ce1821d892b2ff77bb7d1a279ee31a1bc222e3b0

## Design Challenge

사용자는 우선순위 표의 추천이 모두 끝났는지 물었고, 현재 디자인에 강약이 부족하다고 지적했다. 상 항목 네 묶음의 앞선 구현은 완료되었지만 중·하 전체는 완료되지 않았다. 이번에는 이전 추천을 추적하면서 제목, 메뉴, 쓰기 폭, 주요 행동, 표본과 지도의 공간을 실제 화면에서 수정한다.

## EMPATHIZE: Understanding Users

### User Insights

확인된 선호는 3440×1440, 읽기 쉬운 큰 글씨, Instrument Serif 영문과 좁은 자폭의 Freesentation 한글, 차분한 숲과 아이보리, 회화적인 삽화다. 여러 색으로 꽉 채운 블록, 반복적인 노션 양식, 강렬한 장식, 금색 A 인장, 선으로만 그린 손그림은 선호하지 않는다. 이 마지막 제약을 우선하여 큰 색 배경을 추가하지 않는다.

### Key Observations

- 수정 전 일지 작업 제목은 40px, 편지의 제목은 28px, 메뉴는 23px였다. 실제 쓰는 곳이 메뉴·구분선보다 충분히 두드러지지 않았다.
- 수정 전 편지 입력 면은 3440 화면에서 약 1,616px였다. 큰 글씨와 긴 줄 길이는 별개 문제다.
- 메뉴가 가로 면적을 고르게 점유하고, 장 제목·메모·기록의 선이 반복되어 비슷한 힘으로 시선을 끌었다.
- 약초를 펼치면 같은 색인 안에서 설명이 길어졌고, 지도와 일지에도 장 소개가 동일한 비율을 차지했다.
- 모바일에서 저장 버튼과 사진 첨부가 겹치는 중간안을 발견했다. 저장을 글 바로 아래로 옮기고 사진을 선택 펼침으로 수정했다.

### Empathy Map Summary

이전 사용자 발화 검토(User Interviews 자료), Empathy Mapping, Journey Mapping을 사용했다. Says: 강약이 부족하고 큰 글씨가 필요하다. Does: 자신의 모니터와 실제 화면을 보며 밀도·폰트·색·배포를 구체적으로 수정 요청한다. Thinks/Feels는 추론이다: 게임의 분위기를 느끼면서도 다음 행동을 찾기 쉬운 화면을 기대한다. 새 사용자 인터뷰나 실제 플레이 관찰을 수행했다고 보지 않는다.

## DEFINE: Frame the Problem

### Point of View Statement

넓은 화면에서 혼자 플레이하는 사용자는 지금 읽고 조작할 한 곳을 필요로 한다. 모든 메뉴·선·소개가 같은 비중이면, 넓은 여백이 있어도 집중할 곳은 불분명해진다.

### How Might We Questions

1. 글씨를 줄이지 않고 주요 제목과 본문·설명의 비중을 구분할까?
2. 모든 장을 같은 소개와 양식으로 만들지 않고 지도·표본·편지의 쓰임에서 구성을 얻을까?
3. 장식을 늘리기보다 실제 저장과 발견에 작은 변화가 생기게 할까?

### Key Insights

강약은 색의 수보다 크기, 폭, 여백, 선의 강도, 행동의 위치에서 먼저 만들어야 한다. 배경은 조용하게 두고 읽을 제목과 선택된 작업에 힘을 준다. 상태 반응은 현재 기록에 실제로 추가된 경우에만 보여야 한다.

## IDEATE: Generate Solutions

### Selected Methods

SCAMPER Design, Analogous Inspiration(편지·표본첩·여행 지도), Brainstorming, Affinity Clustering. BMAD Party Mode의 Maya(사용 동선), Caravaggio(시각 구성), Sophia(서사)를 같은 세션에서 토의했다. 자동 토의 명단이 비어 있어 이 세 설치된 관점으로 진행했고, 별도 병렬 에이전트나 실제 사용자 패널을 실행하지 않았다.

20. 편지 가장자리와 접힌 귀퉁이를 쓰고 본문 뒤의 질감은 억제한다.

### Top Concepts

- **분명한 작업 제목과 조용한 안내:** 본문 크기 유지, 제목 확대, 소개·메뉴·구분선의 힘 감소.
- **장마다 다른 작업 면:** 편지의 유한한 쓰기 폭, 약초의 선택 표본, 지도의 넓은 지면.
- **정확한 작은 반응:** 새 기록에만 보이는 저장·발견 표시와 계절에 연결된 작은 장식.

토의에서 Caravaggio는 큰 제목과 메뉴의 무게 차이를, Maya는 일지 폭과 저장까지의 거리·키보드 동선을, Sophia는 실제 추가 상태에만 연결되는 책갈피와 표본 반응을 주장했다. 제목만 키우면 장식이 실제 조작을 밀 수 있다는 반론을 반영해 폭과 행동 위치도 함께 바꿨다.

## PROTOTYPE: Make Ideas Tangible

### Prototype Approach

기존 게임 상태와 규칙을 사용하는 실제 React/CSS 시제품을 구현했다. 새로운 게임 규칙이나 저장 포맷을 만들지 않았다. 중간안을 브라우저에서 비교하고 모바일 겹침을 수정했다.

### Prototype Description

- 3440 화면: 일반 작업 제목 56px, 모험의 다음 행동 제목 58px, 생성의 현재 단계 48px, 편지 제목 48px, 본문 26px. 소개 제목은 34px이다.
- 편지: 최대 1,040px. 2,200px 이상에서 편지와 지난 기록을 나란히 두고, 작은 화면에서는 순서대로 읽는다. 저장은 textarea 바로 다음이며 사진은 그 뒤의 선택 펼침이다.
- 표본: 넓은 화면에서는 색인 왼쪽·선택 표본 오른쪽. 좁은 화면에서는 선택 표본을 먼저 보여준다. 펼칠 때 상세에 초점을 옮기고, 접으면 해당 색인 버튼으로 돌아간다. 부위, 조제, 약효, 무게, 횟수, 도구, 관련 원문과 자유 플레이 수동 획득을 보존했다.
- 지도: 소개 비중 22%, 실제 지도 폭 약 1,599px. 편지·약초 소개는 27%로 구성한다.
- 반응: 기존 기록의 첫 로딩·슬롯 전환·복원은 새 발견으로 취급하지 않는다. 직접 기록한 영약재의 실제 ID 추가만 짧게 강조한다. 일지 저장도 실제 state에 존재하는 ID만 책갈피로 알린다.
- 장식: 계절별 작은 채운 식물, 편지 귀퉁이, 얇은 종이 가장자리. 화면 전체의 질감이나 여러 색 면은 추가하지 않았다.
- 사진 선택의 비동기 처리 뒤에도 입력 요소를 안전하게 초기화하도록 event의 입력 참조를 먼저 보관한다.

## TEST: Validate with Users

### Testing Plan

3440×1440을 주 기준으로 삼고 1440×1000, 390×844에서 확인한다. 합성 캠페인은 로컬 미리보기에서만 사용한다. 운영 사이트의 실제 사용자 기록은 수정하지 않는다. 자동 검사는 작동과 회귀를 확인하고, 시각적 만족도는 사용자의 다음 피드백으로 평가한다.

### User Feedback

수정 전에 사용자가 강약 부족을 지적했다. 이 수정안에 대한 새로운 사용자 평가와 실제 사용자 테스트는 아직 없다. Party Mode의 대화와 브라우저 검증을 사용자 인터뷰 결과로 제시하지 않는다.

### Key Learnings

- 9개 장을 세 너비에서 확인: 문서 가로 넘침 0px, 깨진 이미지 없음.
- 생성 8단계를 세 너비에서 확인: 24개 조합에서 가로 넘침·깨진 이미지 없음. 3440 첫 단계 제목 48px, 단계 이동 하단 약 1,149px.
- 3440 편지 폭 1,040px, 본문 26px. 지도 소개 약 589px / 수첩 2,678px, 지도 폭 약 1,599px.
- 표본을 접은 뒤 초점이 `reagent-button-reagent-beech`로 돌아간다. 펼친 뒤 선택 상세에 초점이 도착한다.
- 합성 일지를 실제 저장하고 새로고침하여 제목·내용 복구를 확인했다. 기존 기록 로딩에는 저장 책갈피·새 기록 강조·새 발견 표시가 남지 않는다.
- 모바일 글 입력 하단의 저장과 사진 펼침이 겹치지 않는다. 사진 펼침은 키보드로 열린다. 실제 개인 사진 업로드는 수행하지 않았다.
- 관련 자동 검사 81개, 빌드의 규칙 검사 4개·참조 검사 8개 통과. TypeScript·production build·변경 TypeScript lint·diff 공백 검사 통과. 기존 대형 청크 경고는 남아 있다.
- 추가 모션은 `prefers-reduced-motion: reduce`에서 제거하도록 CSS를 확인했다. OS 설정을 바꿔 직접 모션 감소 재생을 검증한 것은 아니다.
- 브라우저 증거는 이 채팅의 `2026-10-05-rhythm` 시각화 폴더에 저장한다. 실제 운영 배포 결과는 푸시 후 확인하여 최종 응답에 보고한다.
