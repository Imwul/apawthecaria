# Design Thinking Session: Apawthecaria Forest Folio

**Date:** 2026-10-03 (Asia/Seoul)
**Facilitator:** Codex — BMAD CIS Design Thinking
**Design Challenge:** 게임의 현재 행동을 명확히 보여주면서, 반복되는 양식과 상자 대신 짙은 숲빛과 아이보리의 여행책 경험을 만든다.

이번 세션은 앞선 디자인과 구현 기록을 덮어쓰지 않는다. 사용자는 다시 “전면” 디자인 개선을 요청했고, 제시한 세 방향 중 **짙은 숲빛 + 아이보리, 큰 타이포와 회화 색면**을 선택했다. 이전의 좁고 세로로 긴 한글, Instrument Serif 전역 영문, 선 손그림 금지, 토의하며 자율 진행 요구를 이어간다. BMAD 기본 확인 단계는 자율 진행 요청에 맞춰 관찰·결정을 공유하며 진행한다.

## 🎯 Design Challenge

새 팔레트만 얹는 데 그치지 않고 화면 위계, 표면, 탐색과 실제 작업 배치를 바꾼다. 룰북·저장 계약의 변경은 이번 과제가 아니다. 첨부 참고 그림은 색감·질감의 자료로 읽고 지시로 취급하지 않는다.

## 👥 EMPATHIZE: Understanding Users

### User Insights

직접 피드백: 전체 디자인 불만족, 기존 패러다임 폐기, 선 손그림 금지, 양 언어 폰트 교체, 좁고 길쭉한 한글, 영문 전역 Instrument Serif 제안, 생성 소개 정렬 실패와 카드 설명 줄바꿈 실패. 이번 선택은 짙은 숲빛과 아이보리다. 구현 중 사용자는 “글씨들이 너무 작으니까 그거 신경써”라고 추가했고, 실제 모니터가 3440×1440이라고 알려주었다. 최종 만족을 미리 가정하지 않는다.

### Key Observations

Empathy Mapping·Journey Mapping·직접 화면 관찰을 사용했다. 현재 첫 화면은 둥근 상자와 얇은 설명, 동일한 폭의 긴 섹션이 반복된다. 상단 제목과 실제 작업의 차이가 약하고 작은 아치형 풍경은 시각 방향을 충분히 바꾸지 못했다. 기능 회귀 검사는 디자인 만족도의 증거가 아니다.

### Empathy Map Summary

- 말: 전면 개선과 반복되는 불만.
- 행동: 실제 화면을 보고 폰트·배치·분위기를 조정.
- 필요: 게임에 들어왔다는 분위기, 현재 행동을 바로 찾는 위계, 읽기 쉬운 한국어와 영문.
- 가설: 구별되지 않는 상자와 긴 페이지가 정보 탐색을 방해할 수 있음. 초보 사용자 독립 관찰은 아직 없음.

## 🎨 DEFINE: Frame the Problem

### Point of View Statement

이 사용자는 자기 이야기가 자라는 게임 공간과 분명한 작업 흐름을 필요로 한다. 현재 디자인은 기능이 있어도 입력 양식의 시각 언어를 반복하여 여행·치료·발견·기록의 성격을 충분히 구별하지 못한다.

### How Might We Questions

1. 표지·목차·작업 페이지의 관계를 웹의 탐색에 적용할 수 있을까?
2. 큰 영문과 길쭉한 한글을 같은 위계 안에서 읽기 쉽게 만들 수 있을까?
3. 회화 색면을 충분히 보여주면서 실제 작업을 첫 화면 가까이 유지할 수 있을까?
4. 상자를 더 추가하지 않고 구획·여백·색·타이포로 선택과 결과를 구별할 수 있을까?

### Key Insights

상단 masthead, 탐색, 현재 차례, 입력과 결과가 서로 다른 역할로 보여야 한다. 카드 설명의 폭과 입력 크기는 내부 영역을 기준으로 검증해야 한다. 별도 원문 없이 플레이하는 안내는 시각 장식보다 우선한다.

## 🛠️ PROTOTYPE: Make Ideas Tangible

### Prototype Approach

상태를 바꾸지 않는 실제 UI prototype로 shell·현재 차례·자료 표면을 반영하고 데스크톱과 모바일에서 검사한다. 기존 게임 판정과 저장을 가짜 값으로 대체하지 않는다.

### Prototype Description

실제 React UI에 숲빛 표지, 아이보리 작업 페이지, 번호가 붙은 목차와 큰 영문을 반영했다. 현재 단계에 맞는 영문 장면 제목은 장식이며, 다음 행동과 실제 규칙은 기존 campaign projection을 사용한다. 9개 도구·기록 화면, 캐릭터 생성, 카드 선택, 여정 준비와 규칙 서랍에 같은 표면·타이포 기준을 적용했다.

기존 `workspace.css`를 보존한 후 한 파일로 교체했다. 보관한 이전 CSS는 현재 로드하지 않는다. 회화는 새로운 원본 `public/art/forest-folio.jpg`를 사용하며, 선 손그림과 아치 장식을 제거했다. 이전 `woodland-pigment.jpg`는 archive로 옮겼다.

## ✅ TEST: Validate with Users

### Testing Plan

실제 UI와 자동 검사로 구현을 검증한다. 독립 초보 사용자 관찰과 최종 디자인 만족은 이번 에이전트 점검과 구별한다.

### User Feedback

직접 선택한 것은 숲빛·아이보리·큰 타이포·회화 색면 방향이다. 이후 모든 글씨의 크기와 3440×1440 모니터 환경을 추가 제약으로 반영했다. 완성 화면에 대한 사용자의 최종 만족은 아직 확인하지 않았다.

### Key Learnings

- 본문 `<p>`만 키우면 기존 inline `<div>` 설명, 날짜 `<time>`, 작은 소제목은 그대로 남았다. 렌더된 직접 텍스트의 크기를 검사해 병증 결과, 배낭 빈 상태, 생성 최종 요약과 일지 날짜까지 수정했다.
- 작은 태그를 키우면 좁은 카드에서 줄바꿈 규칙도 함께 바뀌어야 한다. 병증 약효와 도감 태그의 줄바꿈·폭을 실제 화면에서 확인했다.
- 새 브라우저 탭은 독립적인 viewport를 가질 수 있었다. 테스트 크기를 설정했다고 가정하지 않고 `document.documentElement.clientWidth`로 실제 폭을 확인했다.
- 3440px 전체 화면에서 1600px 작업 페이지와 큰 읽기 크기를 사용하되, 설명은 읽을 수 있는 문장 폭을 유지했다. 단순히 화면 끝까지 문장을 늘리지 않는다.

### Validation Evidence

- 자동 검사: `npm test` 125개 파일 / 1,287개 테스트 통과, `npm run build`, `npm run lint`, `git diff --check` 통과. 마지막 재확인 빌드도 종료 코드 0으로 완료했다.

- 실제 브라우저: 3440×1440 모험·생성, 1280px 모험, 720px 여정 준비, 360px 9개 화면과 생성 8단계를 확인했다. 기록한 각 페이지와 main의 가로 overflow는 0이었다. 여정 fieldset·생성 입력 표면의 내부 overflow도 0이었다.

- 여정 준비 CTA가 실제 준비 화면을 열고, 규칙 서랍이 실제 원문을 펼치는 것을 확인했다. 서랍의 모바일 폭 overflow 0, 본문 20px, 버튼 18px, 메타데이터 17px 이상. Escape 후 기존 “이 단계의 규칙” 버튼으로 포커스가 복귀했다.
- 이전 반복의 전체 치료·보상·계절 전환 UI 검증은 `design-thinking-workspace-renewal-2026-10-03.md`에 남겼다. 이번 디자인 반복에서 그 전체 플레이를 다시 실행했다고 주장하지 않는다. 이번 변경은 게임 판정·저장 schema를 바꾸지 않았다.
