# Design Thinking Session: Forest Folio — Visual Refinement

**Date:** 2026-10-03 (Asia/Seoul)
**Facilitator:** Codex, 사용자 피드백에 기반한 BMAD 디자인 씽킹
**Design Challenge:** 현재 여행책의 정체성과 제품을 보존하면서 위계·간격·조작을 정교하게 다듬는다.

## Design Challenge

사용자가 붙여넣은 「Visual Sophistication & Design Refinement Pass」를 이번 작업의 범위로 삼는다. 이전 전면 재설계 요청보다 이번 보존 제약을 우선한다. 디자인 시스템과 실제 9개 화면을 먼저 읽고 변경 전 증거를 저장했다. 새 미감, 기능·데이터·메뉴 재편은 범위 밖이다.

설치된 `bmad-cis-design-thinking/SKILL.md`, 전체 design-methods.csv, template.md와 기본 customize.toml을 사용한다. 프로젝트의 BMAD resolver가 없으므로 중립 기본값으로 단계를 수동 적용한다. 프로젝트 BMAD 설치를 완료했다고 주장하지 않는다. 단계별 대기 대신 사용자가 앞서 승인한 “토의하면서 알아서 진행”에 따라 관찰과 결정을 알리고 구현한다. 외부 사용자 연구를 수행했다고 주장하지 않는다.

## EMPATHIZE: Understanding Users

### User Insights

- 사용자는 작은 글씨, 틀어진 줄 맞춤, 영한 서체의 부조화를 반복해서 지적했다.
- 좁고 길쭉한 한글, 현재 영문 서체, 숲빛·아이보리와 회화 색면을 선택했다. 선 손그림은 제외한다.
- 3440×1440 모니터를 사용한다. 화면을 조밀하게 만들기 위해 읽기 크기를 희생할 수 없다.
- 이번 요청은 같은 제품의 정교한 편집이다. 실제 게임을 하는 사람의 현재 위치·조작·보조 정보가 명확해야 한다.

### Key Observations — Implementation Audit

9개 주요 화면의 DOM·실제 스크린샷, `DESIGN_SYSTEM.md`, `workspace.css`, 공통 안내·장 제목 컴포넌트와 일지 JSX를 조사했다. 비교 기준은 1280×1000, 3440×1440, 360×900이다.

1. **잘 작동하는 부분:** 숲빛 표지, Instrument Serif/Freesentation 조합, 번호 목차, 회화 판면, 일지의 기억·판정 구분과 얇은 행 구분선. 흰 바탕 대시보드로 바꿀 이유가 없다.
2. **미해결 부분:** 자료 장의 영문·분류·한글·설명·통계·도움말이 한 줄씩 쌓인다. 넓은 화면 오른쪽은 비어 있고 실제 도구가 아래로 밀린다. 3440 이야기 화면의 장 도입은 369.7px, 안내 213.8px, 작업 시작점은 y=1001px이다.
3. **완성도를 낮추는 부분:** 보조 길잡이가 주 작업처럼 채워진 큰 상자/버튼을 갖는다. 일지 작성은 회색 둥근 상자 안에 사진 업로드 상자가 다시 들어간다. 여정의 두 선택 구획도 반복 사각 틀로 나뉜다.
4. **시각적 잡음:** 일지 불러오기 label이 h2의 크기/굵기를 물려받는다. 이전 button hover 이동, 회색 기본 버튼, 구리색 랜덤 버튼, 둥근 사진 선택/추천 이유 버튼이 공통 조작 문법과 어긋난다. 일부 보조 색상은 대비가 낮다.
5. **다듬기의 기반:** 표지·목차·아이보리 연속 페이지·큰 영문 장 제목·한글 실무 제목·회화는 보존한다. 새로운 장식보다 이 요소의 관계를 편집한다.

### Empathy Map Summary

선택한 방법은 User Interviews(기존 직접 피드백), Empathy Mapping(근거/추론 분리), Journey Mapping(9개 화면 이동), Shadowing 관점의 실제 UI 관찰이다. 별도 인터뷰나 사용자 관찰을 새로 진행하지 않았다. 사용자는 “글씨가 작다”, “전체 디자인이 마음에 안 든다”라고 말했다. 기록/검색을 읽고 조작해야 한다. 혼란·피로의 가능성은 디자인 가설이며 측정된 사용자 감정은 아니다.

## DEFINE: Frame the Problem

### Point of View Statement

여행과 기록을 오가는 약제사는 큰 글씨와 책의 개성을 유지한 채 작업과 보조 정보의 차이를 알아야 한다. 지금은 읽기 크기를 확보한 뒤 역할 간 관계와 공간을 정리하지 않아 여러 요소가 비슷한 강조를 받는다.

### How Might We Questions

- 같은 내용과 순서를 유지하면서 장 도입의 수직 나열을 더 의도적인 구도로 바꿀 수 있을까?
- 글씨를 줄이지 않고 보조 안내를 주 작업보다 조용하게 만들 수 있을까?
- 반복되는 테두리를 타이포·간격·구분선으로 대체할 수 있을까?
- 버튼이 제목 크기를 물려받지 않고 어디서나 같은 위계와 상태를 가질 수 있을까?

### Key Insights

“밀도 개선”은 글씨 축소가 아니다. 같은 콘텐츠를 역할에 맞게 묶고 중복된 프레임을 줄인다. 순수 장식 영문은 정체성, 실제 한글 제목은 작업 위치, 본문은 정보, 메타데이터는 주석이라는 관계를 명확하게 한다.

## IDEATE: Generate Solutions

### Selected Methods

SCAMPER Design(불필요한 프레임 제거), Analogous Inspiration(현재 책의 장 도입과 본문 관계), Brainstorming(공통 수정 대안), Affinity Clustering(위계·간격·상태로 묶음).

### Generated Ideas

1. 장 도입을 데스크톱에서 영문 왼쪽/실무 정보 오른쪽의 두 열로 편집한다.
2. 모바일은 기존 읽기 순서를 유지한다.
3. 영문 제목 크기를 추가로 키우지 않는다.
4. 한글 장 제목을 섹션 제목과 명확히 구별한다.
5. 장 통계는 17px 이상인 메타데이터 역할을 갖는다.
6. 장 도입 설명의 줄 길이를 제한한다.
7. 구획 사이 24/32px, 같은 정보 사이 8/12px의 간격을 공유한다.
8. 길잡이의 사방 테두리를 없애고 왼쪽 선을 남긴다.
9. 길잡이의 일반 CTA를 보조 조작으로 표시한다.
10. 긴급 길잡이는 명확한 주의색과 행동 강조를 유지한다.
11. 모험의 접힌 도움말·다른 행동은 얇은 선으로 연결한다.
12. 여정의 두 fieldset은 내용과 legend를 유지하며 상단 구분선으로 편집한다.
13. 추천 이유 버튼은 동일한 작은 모서리와 높이를 쓴다.
14. 랜덤 카드 뽑기는 주 확정 행동보다 낮은 강조를 준다.
15. 공통 입력 표면·경계·포커스를 통일한다.
16. 버튼 hover의 수직 이동을 없앤다.
17. disabled를 불필요하게 흐리게 만들지 않는다.
18. 일지 도구를 h2 바깥의 공통 도구 영역으로 옮긴다.
19. 파일 선택을 키보드로 접근할 수 있게 하고 focus-within을 표시한다.
20. 일지 작성과 사진 첨부의 중첩 상자를 선과 간격으로 교체한다.
21. 이미 잘 작동하는 일지 행 구분과 기억/판정 구조는 유지한다.
22. 주석색 대비를 높인다.
23. 글꼴을 교체한다 — 사용자 보존 제약과 기존 선택 때문에 기각한다.
24. 길잡이를 다른 화면/순서로 옮긴다 — 구조 변경이므로 별도 UX 과제로 기록한다.

### Top Concepts

- **장 도입 편집:** 기존 영문과 한글 정보를 같은 도입 안에서 묶고 정렬한다.
- **연속 작업 페이지:** 도움말·입력 구획의 중첩 프레임을 줄이고 정보 간격을 정돈한다.
- **일관된 조작:** 주/보조 버튼, 입력, 파일 선택, 선택/포커스/비활성 상태를 공유한다.

## PROTOTYPE: Make Ideas Tangible

### Prototype Approach

실제 로컬 UI에서 shared CSS와 기존 재사용 요소를 먼저 수정한다. 현재 문구·데이터·이벤트 핸들러를 보존하며 최소 JSX 편집은 시각적 역할과 파일 선택 접근성에 한정한다. 같은 상태·viewport의 전후 화면으로 가설을 비교한다.

### Prototype Description

`workspace.css`의 기존 규칙을 편집하고 읽기 기준의 과한 selector specificity를 낮췄다. 공통 역할 크기(본문 1.25rem, 조작 1.125rem, 주석 1.0625rem, 장 제목 2rem)와 8/12/24/32px 간격을 사용한다. 기존 읽기 최소 기준을 유지하면서 메타데이터와 파일 선택의 역할이 상속에 묻히지 않게 했다.

- 장 도입: 넓은 화면은 영문 왼쪽/한국어 제목·설명·주석·도구 오른쪽. 모바일은 기존 순서를 유지한다. 한글 장 제목은 32px, 모바일 28px, 넓은 화면 40.5px다. 영문을 추가로 키우거나 새 장식을 넣지 않았다.
- 안내: 길잡이는 사방 테두리와 채운 면 대신 왼쪽 선과 간격을 사용한다. 일반 길잡이 CTA는 보조 스타일, 긴급 안내는 기존 강조와 행동을 유지한다.
- 입력 구획: 여정 fieldset과 생성 단계의 중첩 프레임을 상단 선으로 정리한다. 여정 360px fieldset은 내부 폭 308px를 쓰고, 카드 설명은 한 열로 내려온다.
- 조작: 공통 주 버튼은 숲빛, 보조/카드 뽑기/파일 선택은 윤곽선이다. 기존 hover 수직 이동을 제거하고 색 변화로 피드백을 준다. 선택 모드의 aria-pressed와 실제 색, disabled의 기능을 보존한다. 비활성 환자 참고도 읽을 수 있는 대비를 유지한다.
- 일지: 백업·불러오기 도구를 h2에서 분리해 제목 크기의 상속을 해결했다. 작성·사진 첨부의 중첩 상자와 원형 버튼을 정리했다. 두 파일 입력은 투명한 실제 input으로 키보드 접근과 focus-within을 제공한다. 파일 핸들러·저장 내용·문구는 동일하다.
- 병증: outer card와 설명 배경을 줄이고 등급·기한은 주석 크기로 분리한다. 성공·실패의 비교 구획, 의미가 있는 약효 표시와 원문 결과는 유지한다.
- 표지/목차: 작은 보조 글씨의 대비를 높였다. 데스크톱 주 목차는 18px, 영문 보조는 17px다. 기존 모바일/넓은 화면의 크기 규칙은 유지한다.
- 조작 경계는 구조선보다 뚜렷한 별도 토큰을 사용한다. 밝은 입력 표면 `#fffdf6`에 대해 기존 `#c3c8b3`의 약 1.69:1에서 `#7d8a77`의 약 3.57:1로 경계 대비를 높였다. 조용한 구분선은 그대로 두어 입력/버튼과 구획을 구별한다. 이 수치는 두 색의 상대 휘도 계산이며 전체 접근성 인증을 의미하지 않는다.

이번 코드 변경은 `workspace.css`, `index.css`의 읽기 selector 한 줄, `App.tsx`의 표시 역할과 파일 입력 JSX에 한정한다. 이전 게임 수정이 들어 있는 큰 dirty diff와 이번 변경을 혼동하지 않는다. 이전 CSS는 `output/design-archive/forest-folio-before-refinement.css`로 보존했다.

### Key Features to Test

9개 화면의 위치/내용/조작 위계, 모바일 overflow와 읽기 크기, 장 도입 높이/작업 시작점, 반복 버튼 크기, 메뉴·도움말·검색·서랍·선택 양식·빈 결과·포커스 복귀. 실제 데이터 생성·삭제·업로드·출발 확정은 하지 않는다.

## TEST: Validate with Users

### Testing Plan

1280×1000, 3440×1440, 360×900에서 동일 상태를 비교한다. 720px 내부 양식도 확인한다. 기존 테스트·lint·build와 실제 DOM/화면을 구별해 기록한다. 사용자 만족도는 결과를 보여 준 뒤 직접 피드백으로 확인해야 한다. 권장 후속 연구는 초보/기존 플레이어 5–7명의 기록 찾기·약효 검색·규칙 확인 작업 관찰이다.

### User Feedback

이번 수정 후 직접 피드백은 아직 없다. 이전 요구와 붙여넣은 요청만 근거로 사용한다.

### Key Learnings

**같은 상태의 전후 관찰:** 3440×1440 이야기 화면에서 장 도입 높이는 369.7→309.0px, 안내는 213.8→157.6px, 작업 시작점은 y=1001.0→889.0px다. 본문은 22.5px, 주석은 19.125px, 버튼과 파일 선택은 동일한 20.25px, 작업 폭은 1600px다. 글씨 축소 대신 정렬과 프레임 편집으로 약 112px를 확보했다. 이는 공간 측정이며 작업 시간 개선을 입증하지 않는다.

1280×1000에서 도입/안내가 주 작업보다 조용해졌고 백업·불러오기 크기가 18px로 같아졌다. 일지 본문은 기존 행 구분·기억·판정 구분을 그대로 유지해 전후를 대조할 수 있다. 360×900은 기존 읽기 순서와 본문 20px, 조작 18px, 주석 17px를 유지한다. 모바일에서는 반복 길잡이와 도입 내용이 여전히 본문을 아래로 밀어내므로 시각 편집만으로 해결됐다고 주장하지 않는다.

**실제 UI 검증:**

| 범위 | 결과 |
| --- | --- |
| 1280×1000의 9개 주요 화면 | page/main 가로 overflow 0 |
| 360×900의 9개 주요 화면 | page/main 가로 overflow 0; 일반 직접 텍스트 17px 미만 없음 |
| 지도·상태 그래픽 | 지도 심볼과 배낭 명성의 작은 체크 마크는 본문과 구별해 유지 |
| 3440×1440 이야기 | 폭 1600px, 본문 22.5/조작 20.25/주석 19.125px, overflow 0 |
| 720px 여정 양식 | fieldset 660px, card 112+524px, 내부 overflow 0 |
| 360px 여정 양식 | fieldset/card 308px, 한 열, 내부 overflow 0 |
| 캐릭터 생성 8단계, 360px | page/단계 내부 overflow 0; 실제 입력 18px; 확정하지 않음 |
| 일지 불러오기·사진 선택 | Tab으로 실제 file input 접근; label에 3px 포커스 표시 |
| 약초 검색 | 존재하지 않는 검색어의 빈 결과/해제 확인; 조건 및 데이터 변경 없음 |
