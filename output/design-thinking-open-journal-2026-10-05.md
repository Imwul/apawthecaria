# Design Thinking Session: Apawthecaria — 펼친 여행 수첩

**Date:** 2026-10-05
**Facilitator:** Codex, 사용자 선호와 화면 증거를 바탕으로 BMAD Design Thinking 적용
**Design Challenge:** 3440×1440에서 차분한 whimsical 여행 게임으로 느껴지면서, 큰 글씨로 다음 행동과 규칙을 읽을 수 있는 사이트.

## Design Challenge

기존 사이트는 배경과 작은 삽화는 부드러워졌지만, 1600px 폭의 한 문서 안에서 동일한 삽화와 양식이 반복됐다. 3440 화면의 양옆이 크게 비고 게임 도구가 세로로 늘어져, 사용자가 계속 지적한 ‘노션 같은 인터페이스’가 남아 있었다. 꾸밈을 늘리는 것만으로 해결하지 않고 실제 화면 구조를 다시 구성한다.

## EMPATHIZE: Understanding Users

### User Insights

사용자 직접 발화: ‘글씨들이 너무 작다’, ‘3440 1440이 내 모니터’, ‘선으로 된 손그림 그리지 마’, ‘너무 정신사납고 강렬해’, ‘노션 같은 인터페이스’. Instrument Serif 영문, 길고 좁은 한글 글자, 숲과 아이보리, 회화 색면을 선호했다. 토의하면서 자율적으로 구현하고 푸시하라고 요청했다.

### Key Observations

현재 배포와 코드의 기준 커밋은 48b0aed. 실제 브라우저 3440×1440에서 책 면의 폭은 1600px, 좌우 각각 920px 여백이었다. 온보딩은 작은 삽화+설명과 큰 흰 양식 카드였다. 모든 장에 같은 오소리 삽화를 사용했다. 개인 일지 첫 화면은 네 개의 캐릭터 배경 메모 양식이 새로운 글쓰기보다 먼저 나타났다.

직접 사용자를 관찰한 Shadowing 또는 실제 사용자 Usability Testing을 했다고 주장하지 않는다. 이번 근거는 대화에서 얻은 User Interview 자료, Empathy Mapping, 작업별 Journey Mapping, 브라우저에서 수행한 대리 시나리오 검증이다.

### Empathy Map Summary

- 말: 사이트 자체가 달라지길 원한다. 부드럽고 장난스러운 정서는 좋아하지만 강한 장식은 불편하다.
- 생각(추론): 화면에서 게임의 세계와 플레이 도구를 동시에 경험하고 싶다.
- 행동: 여러 디자인을 직접 보고 글씨·정렬·배포 상태를 반복해서 지적했다.
- 감정(추론): 표면만 바뀌는 디자인에 피로를 느끼며, 충분한 자율성과 시간을 허용했다.

## DEFINE: Frame the Problem

### Point of View Statement

큰 모니터로 혼자 플레이하는 약제사는 현재 기록과 다음 행동을 넓은 화면에서 쉽게 읽고, 모든 장을 같은 양식으로 처리하지 않는 게임 수첩을 필요로 한다.

### How Might We Questions

1. 넓은 화면을 어떻게 ‘더 넓은 입력란’ 이상의 경험으로 만들까?
2. 서사와 규칙을 동시에 볼 수 있게 하면서 시각적 경쟁을 줄일까?
3. 약초·배낭·일지를 실제 다른 물건처럼 구성할까?
4. 회화 장식을 기능과 분리해 잘못된 상태 정보로 보이지 않게 할까?

### Key Insights

공간의 역할을 나누고, 반복하는 흰 카드와 단계 버튼을 줄인다. 왼쪽은 표지·현재 맥락·대표 행동, 오른쪽은 현재 작업과 자세한 규칙이다. 글씨는 초광폭 본문 26px, 조작 글씨 23px, 주요 제목은 40px 이상으로 두되 한 줄 길이를 제한한다.

## IDEATE: Generate Solutions

### Selected Methods

Analogous Inspiration(여행 수첩·표본첩·편지), SCAMPER Design(단일 문서 대체, 양식 카드 제거, 캐릭터 배경 기록의 위치 재조정), Brainstorming, Affinity Clustering을 사용했다.

### Generated Ideas

1. 펼친 책의 두 면을 만든다.
2. 왼쪽에 맥락, 오른쪽에 행동을 둔다.
3. 장별 색을 낮은 채도로 달리한다.
4. 책 위쪽의 색인 탭으로 이동한다.
5. 배경은 단색 계열로 숨을 둔다.
6. 장마다 다른 회화 삽화를 배치한다.
7. 큰 풍경 한 장으로 여정을 소개한다.
8. 약초 장을 표본첩으로 만든다.
9. 편지와 꽃으로 기록 장을 소개한다.
10. 글쓰기 면에 읽기 간격과 같은 줄을 둔다.
11. 기록 시작 메모는 필요할 때 펼친다.
12. 원문·규칙 링크는 모든 장에 남긴다.
13. 캐릭터 생성 단계를 세로 색인으로 만든다.
14. 뽑을 카드와 해설을 같은 높이에 배치한다.
15. 빈 카드에 식물 회화를 사용한다.
16. 큰 모니터에서는 목적지와 목표를 나란히 놓는다.
17. 작은 화면에서 두 면은 자연스럽게 한 면씩 이어진다.
18. 모바일에서 생성 면으로 바로 내려가는 행동을 제공한다.
19. 배낭 상태를 좁은 여섯 카드 대신 세 열의 기록으로 만든다.
20. 활성 보조 장 이름을 ‘자료·기록’ 색인에 표시한다.
21. 입력란 너비와 문장 길이에 상한을 둔다.
22. 여러 장의 가로 넘침을 실제 DOM에서 확인한다.

### Top Concepts

펼친 수첩, 장별 물건의 성격, 현재 작업 중심 글쓰기로 수렴했다. BMAD Party Mode의 단일 세션 관점 토의에서 Caravaggio는 두 면의 공간을, Maya는 서로 다른 역할과 현재 행동의 집중을, Sophia는 표본·채비·편지라는 서사적 차이를 제안했다. 이는 한 세션의 관점 토의이며 독립 에이전트가 실제로 병렬 작업했다고 주장하지 않는다.

## PROTOTYPE: Make Ideas Tangible

### Prototype Approach

실제 React/CSS 구현으로 기존 게임 동작을 실행하며 검사한다. BMAD 프로젝트 실행 스크립트가 없어 설치된 스킬의 기본값으로 진행했다. 사용자 ‘알아서’ 요청에 따라 단계마다 승인을 기다리지 않았다.

### Prototype Description

- 3440 기준 최대 2680px 펼친 수첩, 33% 맥락 면과 67% 작업 면.
- 기존 woodland-spread에 실제 두 면의 레이아웃 적용. 모험에도 명시적 wrapper 추가.
- 약초·자료실·발견에는 식물 표본, 기록에는 편지, 지도·여정에는 풍경, 배낭에는 여행 동물 삽화.
- 캐릭터 생성은 8단계 세로 색인과 현재 기록 면으로 구성. 모바일은 2열 색인과 빠른 시작.
- 일지의 시작 기록은 접근 가능한 details로 접고, 현재 기억 작성과 지난 이야기를 앞세움.
- 새 회화 두 장은 built-in image_gen으로 생성. WebP 변환 시 알파 보존. 실제 영약재 종을 표시하는 삽화가 아닌 장식이므로 빈 alt와 aria-hidden 사용.
- 고정 금색 A 인장, 강한 반복 벽지, 선화는 추가하지 않음.

### Key Features to Test

9장 이동, 규칙 열기, 카드 입력, 단계 전환과 초안 저장, 약초 검색·펼침, 일지 작성·저장, 모바일 가로 넘침, 넓은 화면 글꼴·공간.

## TEST: Validate with Users

### Testing Plan

3440×1440, 일반 데스크톱, 모바일에서 대표 작업을 실행하고 모든 장의 너비를 검사한다. 기존 45개 프레젠테이션·접근성·모바일 검사, 규칙 및 참조 검증, TypeScript·lint·production build를 수행한다.

### User Feedback

이번 구현에 대한 사용자 만족도 피드백은 아직 받지 않았다. 최근 ‘마저 해줘’는 구현 계속 요청이며 시안 승인으로 해석하지 않는다.

### Key Learnings

초기 구현에서 배낭의 여섯 열이 일반 화면에서 좁아짐을 발견해 세 열로 수정했다. 일지 시작 메모 네 개가 글쓰기를 밀어내는 것을 확인해 접는 첫 기록으로 바꿨다. 기존 입력 스타일의 높은 CSS 우선순위가 편지 줄과 레이아웃별 글씨를 덮는 것을 찾아 범용 입력 선택자의 우선순위를 낮췄다. 모바일의 br 숨김으로 단어가 붙는 문제를 수정했다.

## Next Steps

### Refinements Needed

이번 결과에 대한 실제 사용자의 시각적 선호는 배포된 화면에서 확인한다. 인터랙션 안정성과 시각 만족도는 별개로 판단한다.

### Action Items

최종 검사와 배포 결과는 아래에 덧붙인다. main 및 작업 브랜치로 일반 fast-forward push 후 Production 배포와 실제 사이트를 확인한다.

### Success Metrics

초광폭 양쪽 면이 함께 사용되고 현재 행동이 식별된다. 대표 화면에서 가로 넘침이 없다. 기존 규칙과 기록 동작 검사들이 통과한다. 실제 운영 도메인이 새 코드와 이미지를 제공한다.

### Implementation Validation

- 3440×1440, 1440×1000, 360×800에서 9개 장을 실제 브라우저로 이동하고 문서 가로 넘침 0px을 확인했다. 활성 장은 각각 하나다.
- 390×844 캐릭터 생성에서 수동 카드 입력·동물 선택·다음 단계·초안 복구를 실행했다. 생성 바로가기는 작성 면으로 내려가고 그 면에 키보드 초점을 둔다.
- 3440 화면 본문 26px, 입력 글씨 23px, 첫 기록 영문 제목 104px, 편지 쓰기 줄 배경을 computed style로 확인했다.
- 약초 검색과 상세 펼침, 상황별 규칙 열기·닫기를 실행했다. 로컬 시험 캠페인에서 일지를 작성하고 새로고침 후 제목과 기록이 남아 있음을 확인했다. 운영 캠페인에는 시험 기록을 넣지 않았다.
- 여정의 목적지 선택 면이 여러 행을 차지할 때 내부 버튼까지 늘어나는 문제를 발견해 내용의 상단 정렬을 적용했다. 최종 선택 버튼은 52px이다.
- 프레젠테이션·접근성·모바일 검사 45개와 규칙 검증 4개·참조 검증 8개를 통과했다. TypeScript 및 production build도 통과했다. 기존 대형 App 청크 경고는 남아 있다.
- 운영 배포 확인은 push 이후 별도로 수행한다. 위 결과는 구현 검증이며 실제 사용자의 만족도 평가를 대신하지 않는다.
