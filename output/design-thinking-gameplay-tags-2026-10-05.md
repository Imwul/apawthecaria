## EMPATHIZE: Understanding Users

### User Insights

사용자가 이전 사이트의 영문 전용·색별 태그가 플레이하기 편했다고 명확히 설명했다. 여러 색으로 가득 찬 큰 블록을 싫어한다는 이전 요청과 함께 해석한다. 배경·장식은 조용하게 유지하되, 게임의 식별 부호인 태그는 색을 유지해야 한다. 큰 본문, Instrument Serif 영문, Freesentation 한글, 채운 회화 삽화, 선 그림과 A 인장 제외를 유지한다.

### Key Observations

기존 태그는 표시 함수 두 종류와 여러 색상 규칙에 흩어져 있었다. 진료와 채집에서는 한 색으로 평준화되거나 번역이 붙고, 세계 기록에는 다른 색이 사용됐다. 일부 오래된 색의 글자는 대비가 낮았다. 작은 안내 영역의 CSS는 새 태그까지 17–20px로 줄였다.

### Empathy Map Summary

User Interviews 자료로 기존 발화를 검토하고 Empathy Mapping과 Journey Mapping을 적용했다. 실제 신규 인터뷰는 하지 않았다. Says: 영문명·색 구분이 게임하기 편하다. Does: 모험·도감·가방을 오가며 요구와 재료를 비교한다는 발화에서 동선을 추론한다. Thinks/Feels: 분위기를 좋아하면서 게임의 색인을 즉시 알아보고 싶다는 가설이다.

## DEFINE: Frame the Problem

### Point of View

혼자 플레이하는 약제사는 같은 약효를 모든 화면에서 같은 이름·색으로 읽을 필요가 있다. 번역 중복과 서로 다른 색 규칙은 같은 재료를 다시 해석하게 만든다.

### How Might We

1. 배경을 다채로운 블록으로 채우지 않고 태그만 분명하게 구분할까?
2. 숫자·대안 처방·별도 회분을 잃지 않고 환자와 가방을 비교할까?
3. 새 발견과 저장된 옛 기록을 정확하게 구분할까?

## IDEATE: Generate Solutions

### Methods and Party Discussion

SCAMPER Design, Analogous Inspiration(색인표·표본 라벨), Brainstorming, Affinity Clustering을 사용했다. Party Mode는 같은 세션의 Maya·Caravaggio·Sophia 관점으로 진행했다. 설치된 기본 명단이 비어 있어 임시로 이 세 관점을 사용했고 병렬 에이전트나 실제 사용자 패널을 실행하지 않았다.

Maya는 태그를 게임의 색인으로 보고 영문과 수치를 유지하도록 제안했다. Caravaggio는 배경까지 다색으로 바꾸기보다 라벨에 색을 집중하고 어두운 글자로 대비를 보완했다. Sophia는 처음 불러온 기록을 새 발견으로 표시하지 않아야 한다고 제안했다. 색만으로 상태를 전달하면 어렵다는 반론을 반영해 부족·보유·선택 충족 문구와 수치를 함께 유지했다.

### Generated Ideas

1. 태그 표시는 영문 원명으로 통일한다.
2. 한글 뜻은 검색용 사전으로 유지한다.
3. 22개 태그의 색상표를 하나로 모은다.
4. 태그 글자 대비를 4.5:1 이상 확보한다.
5. FAIR는 금빛, FOUL은 보라빛으로 구분한다.
6. 태그의 수치를 작은 세로 구분선 뒤에 둔다.
7. 넓은 화면의 태그는 26px로 읽게 한다.
8. 좁은 화면에서도 태그를 21px 아래로 줄이지 않는다.
9. 환자·현재 선택·가방의 비교에 동일한 라벨을 쓴다.
10. 색뿐 아니라 충족·보유·부족 문구를 유지한다.
11. 채집의 필요한 약효는 별도 문구로 표시한다.
12. 치료 약효와 거래 가치 행을 구분한다.
13. 필터에서 선택한 영문 태그를 같은 색으로 보여준다.
14. OR·괄호·더하기·별도 회분을 그대로 남긴다.
15. MINIMUM FAIR는 FAIR ≥ 수치로 표시한다.
16. 도감·참조 자료·고분·지난 진료에도 같은 라벨을 쓴다.
17. 장식 이모지는 채운 단색 기능 아이콘으로 정리한다.
18. 주요 완료는 숲색 채움, 보조는 외곽선, 삭제는 붉은 외곽선으로 둔다.
19. 실제 새 세계 기록에만 작은 발견 표시를 붙인다.
20. 변경된 태그를 사용자 저장 데이터에 다시 써넣지 않는다.

## PROTOTYPE: Make Ideas Tangible

### Implementation

공통 RuleTagBadge·RuleTagText·RuleTagValues와 22개 색상표를 적용했다. 카드 문양·상태 ID·판정·저장 원문은 유지한다. 태그 필드의 오래된 번역 형식만 표시 시 정리하며, 개인 일지 문장은 수정하지 않는다. 영문 필터와 한글 약효 검색을 함께 지원한다.

진료·채집 후보·부위 선택 대화상자·배낭·약초·병증·세계 기록·참조 자료·고분의 라벨을 연결했다. 일부 native select의 메뉴 항목은 브라우저 기본 문자 표시를 사용하고, 약초 필터 옆에서 현재 선택의 색을 보여준다.

본문 JSX의 장식 168곳과 조건별 표시 문구 14곳을 정리했다. 주 행동·보조·파괴적 행동의 공통 역할을 주요 기능에 적용했다. 사용자 저장 문장과 룰 카드 문양, 의미 있는 상태 표시는 건드리지 않는다.

## TEST: Validate with Users

### Verification

- 전체 자동 검사 135개 파일·1,374개 테스트 통과. 정상 약효 최대값, FAIR/FOUL 합산·상쇄 등 기존 게임 검사 포함.
- 새로운 태그 검사에서 22개 색의 글자 대비 4.5:1 이상, 서로 다른 배경, 정확한 ID 식별, 오래된 번역 정리, OR·괄호·별도 회분·최소 FAIR·진행 수치 보존 확인.
- 변경 TypeScript lint, TypeScript, production build, diff 공백 검사 통과. 기존 큰 JavaScript 청크 경고는 남는다.
- 로컬 합성 Paw Rot 환자로 실제 체크박스 조작: Frog Slime와 Garden Mint, 주전자와 이빨 선택 시 치료 완료 활성화. 필요한 약효 재료 또는 도구를 빼면 다시 차단됨. 운영의 개인 기록은 이 테스트에 사용하지 않았다.
- 모험·약초·배낭·병증 사전 × 3440×1440, 1440×1000, 390×844: 12개 화면에서 가로 넘침 0px·깨진 이미지 0개. 태그 크기는 26px/21px/21px.
- 한글 통증 검색은 13개 재료를 찾고, PAIN 필터는 영문 표시와 색 라벨을 유지한다.
- 불러온 기존 발견에 새 발견 강조가 나타나지 않는다. 새 ID·정렬 변경·중복·제거·캠페인 전환은 기존 발견 알고리즘 검사로 확인했다. 일반 세계 기록의 실시간 새 발견 표시를 모든 획득 경로에서 직접 재현한 것은 아니다.
- 새 움직임은 모션 감소 CSS에서 제거한다. OS 설정 변경을 통한 재생 검사는 하지 않았다.
