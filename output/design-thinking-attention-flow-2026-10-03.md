# Design Thinking Session: Forest Folio · Structural UX & Attention Flow Calibration

**Date:** 2026-10-03
**Facilitator:** Codex · BMAD CIS Design Thinking
**Design Challenge:** 실제 플레이 중 현재 작업, 참고자료, 복귀 맥락의 주의 흐름을 점검한다.

현재 Forest Folio를 기준으로 삼는다. 시각 정리나 새 정보구조를 만들지 않는다. 폰트·색·회화·장 도입·규칙·콘텐츠·기록·저장 스키마·플레이 절차를 보존한다. 사용자의 첨부 텍스트는 요청문으로 읽었다. 기존 ‘토의하면서 알아서 진행’ 지시에 따라 단계별 중단 대신 근거와 결정을 기록한다. 설치된 BMAD SKILL.md, customize.toml, template.md, 전체 design-methods.csv를 사용했다. 프로젝트의 BMAD resolver가 없어 빈 기본 customization과 output 경로를 사용했으며 설치 작업은 하지 않았다.

## Design Challenge

플레이어가 자료를 찾아보면서도 작성 중인 문장과 현재 작업을 잃지 않고, 필요한 정보에 도착하기 전에 다른 목적의 안내를 반복해서 지나치지 않게 할 수 있는가? 독서·탐험의 여유와 맥락 있는 복잡성은 유지한다.

## EMPATHIZE: Understanding Users

### Methods and User Insights

Journey Mapping, Empathy Mapping, Diary Studies 관점으로 기존 요청·화면 피드백과 실제 UI 왕복을 분석했다. 직접 사용자 인터뷰·shadowing은 수행하지 않았으며 실제 사용자 행동으로 간주하지 않는다. 사용자 근거: 작은 글씨를 피하고 3440×1440에서도 읽기 편하게, 현재 디자인은 보존하되 플레이의 주의 흐름을 확인하라는 요청.

### Key Observations / Empathy Map

- Say: 기존 디자인과 여행책의 성격을 유지하면서 실제 작업을 방해하는 마찰만 줄이기.
- Do (에이전트 UI 검증): 여정 준비 열기, 현재 규칙 서랍, 약초 검색·상세, 기록장 환자 검사, 일지 초안→약초→Back, 자료실 방문.
- Think / Feel: 일지 문장을 잃으면 다시 써야 한다는 부담이 생길 수 있다는 가설. 부담이나 속도는 사용자 관찰로 확인하지 않았다.
- 실제 오류: 일지 제목·본문을 입력한 뒤 약초로 이동하고 Back하면 두 입력 모두 비워진다. 이야기의 선택한 하위 탭도 재진입 시 기본 일지 탭으로 바뀐다.
- 모바일 360×900에서 비긴급 ‘어디로 떠나볼까요 / 여정 준비하기’ 블록이 8개 자료·기록 장에 동일하게 반복된다. 길잡이 높이 323.47px, 약초/이야기 본문 시작 y=1053.03px, 지도/병증/배낭 y=1087.03px. 실제 약초 검색 입력 y=1778.17px, 일지 제목 입력 y=2542.25px. 후자의 모든 거리를 불필요하다고 판단하지 않는다.
- 데스크톱 1280×900 약초 본문 시작 y=765.45px, 실제 검색 입력 y=1107px, 길잡이 147.88px.
- 자료실에서 현재 환자가 없는데도 Introduction / Overview 등 일반 챕터에 ‘현재 질환’ 표식이 붙는다. entry.ownerId와 activeAilmentId가 둘 다 undefined여서 일치하는 조건이다. 실제 맥락과 반대되는 주의 표식이다.

## DEFINE: Frame the Problem

### POV / How Might We

여행 기록을 쓰고 자료를 읽는 플레이어에게는 현재 작업의 연속성이 필요하다. 자료를 열었다는 이유로 문장을 잃거나 일상적인 참고 화면마다 모험을 다시 시작하라는 안내를 받을 필요는 없다.

- 어떻게 일반적인 모험 안내를 삭제하지 않고 필요할 때 펼칠 수 있게 할까?
- 어떻게 현재 긴급 판정은 숨기지 않으면서 자료 작업이 앞서게 할까?
- 어떻게 일지의 기존 임시 상태를 화면 왕복 동안 유지하고 캠페인 교체 시 분리할까?
- 어떻게 현재 질환 표식이 실제 질환이 있을 때만 나타나게 할까?

### Structural suspects verdict

1. 반복 현재 모험 CTA: 비긴급일 때 실제 참고 작업과 직접 관련 없음. 도움말 안으로 이동; 기존 urgent는 전면 보존.
2. 장 도입 뒤 실무 제목: 실제 구역과 하위 작업을 안내하며 단순 동명 복제 아님. 모두 유지.
3. 이야기 하위 탭 vs 자료실/진료 기록: 901 vs 1201, legacy 0 vs canonical 1처럼 다른 내용. 합치지 않음.
4. 모바일 반복 길잡이: 모든 비플레이 장에서 같은 323.47px. 글씨를 줄이지 않고 일반 다음 행동만 접힌 영역으로 이동.
5. 도움말 경쟁: 짧은 장 도입 + 상세 절차/용어는 다른 깊이. 현재 접근/접힘 유지. 헤더 길잡이와 페이지 내 길잡이는 같은 target으로 연결하는 다른 접근 위치라 삭제하지 않음.
6. 모험 메뉴 vs 자료실 복귀: 새로 페이지를 여는 것과 기존 scroll 복구가 다름. 이름대로 보존. 추가 영구 nav/이전 과업 tracking은 만들지 않음.

## Final Findings — A–E

### A. Confirmed friction

1. 자료 왕복 후 미등록 일지 제목/본문과 선택한 이야기 하위 탭 유실.
2. 다른 목적의 비긴급 다음 모험 안내가 8개 자료/기록 장의 현재 작업 앞에 동일하게 반복됨.
3. 환자가 없는데 일반 색인에 ‘현재 질환’ 표식이 표시됨.

### B. Productive complexity

- 장 도입의 영문·현재 맥락·회화·여백은 여행책의 분위기와 방향을 제공한다.
- 자료실과 이야기 세계 도감, canonical 진료 기록과 legacy 이야기 casebook은 다른 데이터/목적이므로 합치지 않는다.
- 초반 캐릭터 기억과 현재 일지 작성, 각 기록 하위 탭은 서로 다른 이야기 역할이다.
- 원문 서랍의 관련 항목·독서 trail·의도적인 펼치기, 상세한 도움말은 자료를 찾아보는 플레이를 지원한다.
- 표지 목차와 자료실 복귀, 헤더 길잡이와 본문 길잡이는 다른 위치/복구 목적이다.

### C. Changes implemented

- PlayGuide: 일반 모험 안내·CTA를 기존 접힌 help 안으로 이동. 기존 urgent 조건은 전면 overview 유지, 모험의 sole primary CTA 유지.
- App/JournalsView: 기존 title/text/photos/subTab 상태를 같은 App 세션 소유로 옮김. 기존 campaign reset에 연결. 닫힌 뷰/교체 캠페인으로 늦은 사진 결과가 넘어가지 않도록 unmount guard 유지. 새 영구 저장/추적/스키마 없음.
- AlmanackPanel: 실제 activeAilmentId가 있을 때만 ‘현재 질환’ 비교.
- CSS·폰트·메뉴·장/실무 제목·설명·일지 등록·규칙·engine·save schema를 새로 바꾸지 않았다.

### D. Suspected issues not changed

- 장 도입 뒤 실무 제목: 다른 구역을 이름 붙이고 목차/도구의 방향을 제공한다. 축소할 증거 부족.
- 이야기 하위 메뉴와 별도 자료/진료 메뉴: 직접 데이터가 다름. 실제 사용자 혼동 관찰 없이 구조 통합하지 않음.
- 시작 이야기와 백업 도구가 일지 작성보다 앞서는 순서: 긴 모바일 거리 자체는 확인됐지만 새 약제사 기억/자료 보관의 유용성을 지우거나 재배치할 근거 부족.
- 빈 여정 준비의 참고 왕복 후 접힘: 아직 작성할 값 없는 상태이며, 의미 있는 준비는 기존 savedJourneyDraft의 복원 구조를 이용한다. 자동 과업 추적을 추가하지 않음.
- 자료실 플레이 복귀가 이전 장과 다를 가능성: 버튼이 명시적으로 ‘플레이’로 가고 Back은 이전 장을 복원한다. 새 nav/의도 추론 없이 유지.

### E. Requires real user observation

5–7명의 신규/기존 플레이어가 동일 과업을 수행하는 모습을 관찰해야 한다. 일반 next 안내를 help 안에서 찾는 데 추가 1회가 적절한지, 시작 이야기와 일지 작성 순서를 실제로 헷갈리는지, 이름 비슷한 진료/자료 목적을 구분하는지, 자연스러운 탐험과 재검색의 경계가 어디인지 확인한다. 다음 실험에서는 수행 시간·입력 유실·반복 탐색·복귀 성공을 실제로 기록할 수 있지만 이번 결과로 시간/만족도 개선을 주장하지 않는다. 사진/클라우드 입력과 여러 미완료 게임 절차가 동시에 있을 때의 독립 사용자 흐름도 아직 관찰하지 않았다. 페이지 reload/앱 종료 시 미등록 일지 초안의 영구 복원은 구현하지 않았고 기존 저장 스키마 제약을 보존했다.

이 세 변경은 직접 관찰한 마찰을 줄이는 범위로 한정했다. 로컬 구현만 완료했으며 배포하지 않았다.
