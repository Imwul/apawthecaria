# Design Thinking Session: Apawthecaria

**Date:** 2026-10-08
**Facilitator:** Codex
**Design Challenge:** 원본 룰북에서 실제 플레이 절차를 독립적으로 재구성하고 웹앱을 플레이 도구로 다시 설계·구현한다.

## Design Challenge

혼자 플레이하는 Poulticepounder는 이동, 조우, 환자 치료, 출발 준비를 반복하면서 여행 일수, 여러 환자의 시간, 재료와 도구, 기록을 함께 관리해야 한다. 현재 화면이나 이전 설계를 전제로 삼지 않고 필요한 정보를 행동 시점에 보여 주어 다음 행동을 찾는 비용을 줄인다.

사용자가 분석부터 구현·검증까지 자율 진행을 명시했으므로 BMAD의 단계별 확인 대신 문서에 근거와 결정을 저장한다. 실제 사용자 인터뷰를 수행한 것으로 표현하지 않으며, 룰북 기반 여정 분석과 시나리오 검증을 구분한다.

## EMPATHIZE: Understanding Users

### User Insights

원본은 220쪽의 Apawthecaria v1.3 PDF다. 현재 앱·번역 데이터·기존 감사 문서를 읽기 전에 룰북을 순서대로 검토했다. 핵심 규칙 1–116쪽과 Almanack 117–220쪽은 병렬 독립 검토했고, 루트 검토자가 전체 순차 텍스트와 절차·경계 조건을 교차 확인했다. 두 캐릭터 시트와 지도 앞·뒷면도 별도로 확인했다.

### Key Observations

- 8–9, 24–25쪽: 이동 → 도착 위치와 계절에 맞는 조우 → 일수 기록 → 현지 환자 치료 → 출발 준비가 반복된다.
- 28–31쪽: 환자 소개, 평판 상한을 적용한 심각도, 질환, 각각의 타이머, 현재·인접 위치의 재료 조사 순서가 필요하다.
- 32–35쪽: 채집/교환 조우를 해결한 뒤 가방을 확인하고 **치료할 수 있으면 먼저 치료**한다. 치료할 수 없을 때 타이머를 감소한다.
- 27, 30쪽: 일반 태그의 효력은 합산하지 않으며, 위치마다 희귀도가 다르다. 희귀 지역과 비수기는 각각 +3이다.
- 36–37쪽: 치료 보상, 평판, 특수 결과, 잔여 시간 활용, 실패 결과, 도시 서비스, 이동 순서를 구분한다.
- 7쪽: 기록은 글 이외의 형태도 가능하며 모든 사건에 필수 입력을 강제하지 않는다.

### Empathy Map Summary

플레이어의 질문은 ‘지금 무슨 단계인가’, ‘어떤 태그가 부족한가’, ‘어디에서 어떤 방법으로 구할 수 있는가’, ‘시간을 줄이기 전에 치료 가능한가’, ‘다음 이동이 가능한가’다. 규칙과 실행 도구를 찾느라 이야기를 중단하는 것이 핵심 마찰이라는 가설을 세운다.

## DEFINE: Frame the Problem

### Point of View / HMW

플레이어는 규칙을 기억하는 데 집중하기보다 지금 필요한 약효와 가능한 행동을 확인하고 이야기를 이어가고 싶다. **어떻게 현재 절차·두 종류의 시간·필요 재료·규칙 원문을 한 작업 흐름에서 확인하게 할까?**

### Priority Problems

1. 실행 허브가 PlayView 마지막에 있어 당장 할 일을 찾으려면 스크롤해야 한다.
2. 모바일에서는 여행/찾기/기록 모드를 바꾸고 세부 도구를 선택한다. 주요 도구 접근 경로가 달라진다.
3. 재료가 없어도 CSS가 조제 패널을 조사보다 먼저 보여 준다. DOM/키보드 순서와 시각 순서도 다르다.
4. 긴 후보 목록이 카드·채집 실행을 밀어낸다. 실제 카드 결과 44개 중 환자에게 필요한 10개가 묻힌다.
5. 환자 필터와 현재 지역·계절 필터가 서로 지워진다.
6. 일반 원문 바로가기가 지정한 29/33/35쪽 대신 절차 첫 페이지를 연다.
7. 준비 도구 없음이 엔진과 부위 선택 UI 모두에서 채집 금지로 해석되었다. 채집과 조제는 다른 단계다.
8. 일반 채집 실패 FP는 허리칼 조건을 요구하지만 엔진/가이드가 무조건 지급했다. 앱 종료는 선택적 저널을 강제했다.

기존 판정 엔진은 상당한 규칙을 이미 지원한다. 복수 기한, OR 조건, 별도 회분, 같은 카드의 채집 조우, 교환의 별도 두 번째 카드, 고분 전용 절차와 지속 효과를 보존하고 실제 접근 구조를 바꾼다.

## IDEATE: Generate Solutions

BMAD ideation을 통해 비교한 18개 아이디어: (1) 모든 판정을 단일 마법사로 직렬화, (2) 지도 중심 작업, (3) 규칙 검색을 첫 화면으로, (4) 현재 단계의 직접 실행 허브, (5) 네 단계 루프, (6) 두 시계 분리, (7) 6개 직접 내비게이션, (8) 보조 기록 disclosure, (9) 진료 조사/조제 전환, (10) 후보 3개+더 보기, (11) 조사 노트/처방 기준 획득 목록, (12) 환자·지역·계절 한 번 적용, (13) 약효→조사 연결, (14) 7개 반복 규칙 바로가기, (15) 현재 단계 원문, (16) 환자 설명·과거 기록 접기, (17) 종료의 선택적 회고, (18) 초점과 열린 패널을 동기화하는 행동 링크.

평가기준은 원문 충실성, 현재 행동 도달 비용, 예외 절차 수용, 화면 밀도, 기존 저장/초안 안전성이다. 단일 마법사는 고분·추가 환자·직접 판정의 비선형 흐름을 좁히므로 채택하지 않았다. 지도 중심은 치료 중 약효 비교에 불필요한 공간을 차지한다. 규칙 검색 중심은 행동마다 검색을 반복하게 한다.

선택한 방향 3개를 하나의 구현으로 결합한다: **현재 단계 작업판**, **진료의 조사/조제 작업대**, **상황별 원문과 조합 가능한 도감**. 과거 화면 배치나 중복 기능 보존은 판단 기준으로 삼지 않는다.

## PROTOTYPE: Make Ideas Tangible

실제 React/TypeScript 구현을 프로토타입으로 사용했다. 주요 코드:

- JournalExperience + playLoop: 6개 직접 도구, 보조 기록 3개, 현재 단계 표시, 달력 일수/치료 시간, 실제 적용 처방 표시.
- App: 실행 허브를 절차 앞에 배치, 하나의 다음 행동 강조, 중복 진료 타일/고분 요약 제거, 조사·조제 중 한 작업을 펼침. 내부 선택을 유지하며 초점을 이동한다.
- QuickRules + quickRules: 상황에 맞는 3개 반복 규칙과 접힌 나머지 4개, 각각 원문 페이지로 연결.
- RulebookReferenceDrawer + sourceSelection: 유효한 요청 페이지 우선, 관련 항목 이동/뒤로가기 원문 복원.
- 도감: 환자/지역/계절 필터를 조합하며 한 번에 적용. 치료 약효에서 조사로 연결.
- foragingEngine/App: 채집과 준비 도구 분리. 치료 단계의 도구 요구는 유지. ordinary miss에 정상 허리칼 조건 적용.
- journeyEngine/App: 빈 회고로 명시적 종료 허용, 시스템 기록과 플레이어 기억 구분.
- ReaderGuide/playGuide/한국어 룰북: 수정된 FP 조건과 도구 예외를 함께 안내.

모바일 첫 검증에서 상황 카드가 다음 행동을 첫 화면 밖으로 밀어냈다. 상단 브랜드·상태·루프를 줄이고 상세 환자 설명을 접었다. 패널을 접은 상태와 전환 버튼이 어긋나는 경우, 미완료 획득보다 재료 보유가 먼저 조제를 여는 경우를 발견해 수정했다.

## TEST: Validate with Users

실제 사용자 인터뷰나 사용성 연구는 수행하지 않았다. 대신 로컬 앱의 브라우저 시나리오와 자동 회귀를 수행했다. 결과와 화면은 `output/rebuild-verification/report.md`에 저장했다.

- 준비 도구 없는 금잔화 부위 채집, 동일 카드의 숲/봄 조우, 추가 K 카드, 보너스 부위와 시간 정산을 실제 UI로 확인했다. 타이머 8→5, 달력 1일 유지.
- 가방의 BURN/WOUND 부위와 절구 선택 → 빈 메모 → Trading 보상 → 각 부위 1회분 소비 → 여분채집 → Moving On → 속도3 경로 → Obridge 사회 조우 → 달력 2일 → 다음 현지 진료를 실제 UI로 완료했다.
- 원문 요청 29/33쪽과 복귀 상태를 확인했다. 절차 안내는 1회, 영어 원문 펼치기는 추가 1회이며 과장된 ‘원문 1회’ 문구를 고쳤다.
- 320×740, 390×844, 1280×900에서 페이지 가로 넘침 없이 핵심 상태와 주행동을 검토했다. 모바일 직접 내비게이션 6개는 높이44px이며 320px 주행동의 하단은682px다.
- 작업대 닫기/다시 열기, 조사↔조제 전환에서 선택 초안과 접근성 상태가 유지된다.
- 진료 마감은 정상 본문 흐름으로 옮기고 선택 메모를 접었다. 여분채집 출발 버튼은 맨 위 하나, 직접획득 목록은 절차별 접힘으로 바꿨다.
- 진행 중 획득/즉시조제/보상 대기 상태에서 새 획득이 저장 거래를 덮어쓰는 우회 진입점을 실제 App 콜백 회귀로 차단했다.

## Completion and Limits

분석 → 대안 선택 → 구현 → 선정 시나리오/전체 자동 검사까지 수행했다. 구현은 원문 기반 플레이 작업판을 중심으로 하며 고분·복수 질환·OR·반복 회분·서사 선택과 직접 판정 경로를 보존한다.

원본의 중복 rank10, 빠진 동률 지시 등 모호성은 기록하고 임의로 새로운 판정을 만들지 않았다. 모든 Almanack 예외를 브라우저에서 플레이했다고 주장하지 않는다. 실제 사용자 과제 시간과 저사양 기기의 로딩 시간은 측정하지 않았다. 큰 App 번들 경고는 남아 있다.
